Camp v0.10.0-preview.1 introduces allocator-aware lifecycle helpers, making allocator ownership and generated `create()` / `destroy()` behavior more consistent for library APIs.

Camp is still early preview software. Package-management commands remain experimental and are intended mainly for Camp compiler development at this stage.

## Language And Standard Library

- Added allocator-aware lifecycle helper behavior based on `within` policy and constructor/destructor signatures.
- Added retained allocator constructor syntax with `within this.allocator`.
- Generated `create()` helpers now allocate through the selected allocator when lifecycle rules require one.
- Generated retained-allocator `destroy()` helpers now destroy the object and free complete object storage through the retained allocator.
- Updated `List<T>`, `HashMap<K, V>`, and `HashSet<K>` to use retained allocator constructors.
- Interface destructor conformance now requires exact allocator lifecycle shape.

## Fixes

- Fixed `prep new` allocator context lowering.
- Fixed imported API consumers so they use serialized lifecycle helper signatures instead of recomputing helper shape from local policy.
- Fixed allocator lifecycle helper emission for classes that retain allocator provenance.
- Fixed lifecycle API and metadata output for retained allocator constructors and destructors.

## Tooling And Test Output

- Test and coverage modes now report allocator memory totals and leak counts.
- Test leak reporting is suppressed when a test already failed, so the primary failure remains clear.

## Documentation

- Updated construction, destruction, allocation, interface lifecycle, metadata, and LLM coding guidance for allocator-aware lifecycle helpers.

## Compatibility Notes

- Exported class lifecycle helper signatures can change for libraries that use explicit `within` policy or allocator-aware constructors/destructors.
- Classes with allocator-aware construction and destruction may need to use either paired ordinary `within allocator` lifecycle methods or retained allocator syntax.
- Downstream packages that consume generated API headers or metadata should be rebuilt.
