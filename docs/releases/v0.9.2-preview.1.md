Camp v0.9.2-preview.1 focuses on standard-library string cleanup, namespace/API header correctness, virtual dispatch fixes, and much faster no-change rebuilds for projects that use packages or project references.

Camp is still early preview software. Package-management commands remain experimental and are intended mainly for Camp compiler development at this stage.

## Standard Library

- Refreshed the string, `astring`, `wstring`, and string-conversion APIs for the current stdlib shape.
- Removed the redundant `string.toString()` helper; string values are already strings.
- Updated string API documentation and LLM guidance to match the current API names and usage.

## Fixes

- Fixed several namespace and API-header issues involving namespaced type references, delegate parameter types, same-file API references, overload aliases, member namespace visibility, and nominal identity in signatures.
- Fixed namespace-local lookup and iterator API state naming.
- Fixed vtable initialization for generated `create` helpers, including namespaced virtual `create` methods.
- Fixed `finally delete` lowering so virtual destructors dispatch from the correct topmost virtual instance.
- Fixed `campc run` so it runs the executable artifact rather than a copied shared-library dependency.

## Build and Tooling

- Added `--timing` diagnostics for compiler builds.
- Added CLI-level timing so project-reference preparation and executable run time are included in reported timing.
- Improved incremental build behavior for generated C output, package caches, standard-library caches, top-level artifacts, and project-reference outputs.
- Avoided repeated rebuilds caused by unchanged generated outputs retaining stale timestamps.
- Avoided treating bare linker library names such as `user32.lib` as missing local file inputs during freshness checks.

## Compatibility Notes

- Code that explicitly called the removed redundant `string.toString()` helper should use the string value directly.
