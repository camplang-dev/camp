Camp v0.6.1-preview.1 improves standard-library metadata and documentation,
updates the heap allocator API shape, and fixes interface value lowering in
generated C.

Camp is still early preview software. Package-management commands remain
experimental and are intended mainly for Camp compiler development at this
stage.

## Compatibility Notes

`HeapAllocator` is now a standard allocator value:

```camp
within (HeapAllocator)
{
	// allocate with the process heap
}
```

Code that treated `HeapAllocator` as a type should use the public allocator
value instead.

The pointer hash policy helper has been renamed:

```camp
auto policy = pointerHashPolicy<int>();
```

Code that called `Ptr_hashPolicy<T>()` should rename the call to
`pointerHashPolicy<T>()`.

## Standard Library

- Added category metadata across the standard library so generated API
  documentation can group declarations by area, such as Collections, I/O, Text,
  Memory, Diagnostics, Date/Time, Synchronization, and Core.
- Added concise documentation for standard array helpers.
- Added documentation and an example for `Console`, including overload-family
  summaries for `Console.write` and `Console.writeLine`.
- Changed `HeapAllocator` to be a public allocator value backed by private
  implementation details.

## Metadata

- Added standalone file metadata attributes. A source file can now use
  `@category("Name");` near the top of the file to provide a default category
  for top-level declarations in that file.
- Extension methods and static extension members inherit category metadata from
  the type they extend when appropriate.

## Fixes

- Fixed C lowering for Camp interface values so interface-typed variables use
  the intended built-in pointer representation.
- Hid private heap allocator implementation details from generated public API
  output.
- Avoided serializing non-inline public API initializers in generated API
  output.
