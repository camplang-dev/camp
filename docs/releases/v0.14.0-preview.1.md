Camp v0.14.0-preview.1 introduces representation and capability based generics, explicit erased storage, and constructed callable and interface contracts. It also adds collection helpers and improves compiler correctness across lifetimes, cleanup, dispatch, numeric typing, and native build caching.

Camp remains early preview software. This release changes generic source and ABI contracts and tightens language checks. Review the compatibility notes and rebuild affected libraries and applications together.

## Features

- Generic parameters now select a representation: omitted `<T>` uses unspecified-size storage, while `<T: R>` selects an integer carrier. Separate `sizeof(T)`, `typenameof(T)`, and `vtableof(T: I)` capabilities supply checked copying and layout, type names, and interface dispatch.
- Added written erased storage and results such as `void<int?>`, preserving complete values behind pointers, in arrays, and in caller-provided result storage. Integer carriers such as `long<Color>` preserve the carried type while selecting its storage representation.
- Added constructed interface and callable newtype ascription, with exact capability contracts and explicitly specialized generic method references such as `box.check<byte>`.
- Added `List.tryGetItem(index, out result)` to distinguish an absent item from an item whose optional value is unspecified, and `List.take` to borrow a range without transferring ownership.

## Fixes

- Fixed generic calls and callbacks involving arrays, optionals, erased results, allocator contexts, and capability forwarding, including calls across generated API boundaries.
- Fixed inherited generic fields and methods, constructed interface dispatch, virtual return and argument handling, and base constructor forwarding.
- Fixed destructor chaining and cleanup on early exits, and improved checks for abstract construction, sealed overrides, shadow classes, and fixed-value copying.
- Fixed error propagation from loop conditions, prepared calls, interpolation holes, and compound expressions. Nested `finally` cleanup now runs before control transfers to an outer catch, and catch storage and scope are checked consistently.
- Fixed property increments and compound assignments, array member and pointer access, configuration-dependent expressions, and loop-variable scope.
- Fixed lifetime checking for retained constructor arguments and allocators, bound method references, static storage, interface receivers, and values derived from retained receiver or parameter content. Invalid escaping interpolation and iterator stack addresses are diagnosed.
- Fixed numeric suffix types, natural integer literal ranges, constant overflow, contextual literal expressions, symmetric numeric operations, and character conversions. Conditional expressions, array literals, and generic calls now select common types consistently; an `out T` argument fixes the exact inferred storage type.
- Improved diagnostics for expressions that supply no inferable type, invalid output arguments, reserved names, allocation contexts, and invalid lifetime annotations.

## Tooling And Editor Support

- Project-reference and native artifact caches now validate content reliably, reuse unchanged inputs despite timestamp changes, and relink when linked library contents change. Static archive membership checks detect external archive changes even when timestamps are preserved.
- Equivalent output-path spellings share the same artifact cache when they resolve to the same directory.
- Generated Camp APIs, metadata, and editor information preserve representation and capability contracts while keeping private payload types hidden from external consumers.

## Documentation

- Updated the language and compiler guides for representation and capability generics, erased storage, callable matching, interface dispatch, allocation and retention lifetimes, destructor cleanup, and error handling.
- Documented numeric literal types, conversions and overflow, common expression types, enum member targeting, and generic inference from input and output arguments.

## Compatibility Notes

- The former `any`, `copyable`, and `implements` generic constraints are removed. Select a representation and declare the capabilities required by the operation. An omitted representation always means unspecified size; it does not imply a machine-word carrier.
- Unspecified-size generic inputs remain indirect. Copying and layout require checked `sizeof(T)` capability, including in generic callbacks. Exact unspecified-size locals require explicit `stackalloc` and size capability; stack storage does not survive `yield` or `await`.
- Rebuild producer and consumer artifacts together when generic representations, capabilities, generated APIs, or callable contracts change. A generic method reference retains its represented result contract; use an explicit adapter when an ordinary result signature is needed. Generic method references require explicit method type arguments.
- Optionals have one level and cannot directly wrap another optional, a type parameter, an erased carrier, or an integer carrier. Ordinary optional values can still be stored whole through erased storage or collections. Use a boolean result plus `out T` when a generic operation must report absence.
- Omitted `out` argument binding and deconstruction syntax are removed. Write each `out` argument explicitly, using `out _` to discard an output.
- Implicit numeric conversions no longer accept signed-to-unsigned or integer-to-character conversions. Character encoding conversions require explicit intent. Previously accepted out-of-range constants, invalid lifetimes, implicit fixed-value copies, and unsafe retention may now be rejected.
- Integer carrier equality compares all carrier bits, including for floating payloads; read the payload as `float` or `double` for numeric equality. Pointer payloads currently require `nint` or `nuint`; fixed-width integer pointer carriers are not supported.
- The standard `Allocator` interface is escaped. Conflicting scoped or unscoped annotations must be removed, and retained custom allocators must satisfy the lifetime of the object retaining them.
