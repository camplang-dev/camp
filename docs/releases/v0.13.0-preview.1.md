Camp v0.13.0-preview.1 adds directory enumeration, typed generic interface witnesses, and consistent call and type specifier syntax, alongside a broad set of compiler-correctness improvements.

Camp remains early preview software. This release tightens several language checks and changes some source and interface ABI contracts; review the compatibility notes before updating existing projects.

## Features

- Added `FileSystem.iterateDirectory` to enumerate immediate entry names in native order. Names borrow the iterator's reusable buffer; copy a name before retaining it beyond the current iteration.
- Added `FileSystem.isDirectory(path, noFollow: true)` to probe an entry without following symbolic links or Windows directory reparse points.
- Generic interface capabilities are now typed witnesses: slots read through `vtableof(T: Interface)` take the concrete `T*` receiver and preserve that contract when copied or forwarded. Generic construction and destruction use the interface lifecycle contract.
- Added `_targetcall` and `_targettype` to explicitly select the target's default calling convention or carrier representation, including as conditional specifier-alias fallbacks.
- Call and type specifiers now use consistent, target-independent syntax recognition with analysis checking names, placement, availability, and alias alternatives.
- Added deletion of escaped delegate values to release their allocated context.

## Fixes

- Fixed a published Native AOT compiler crash when writing or reading native artifact caches.
- Fixed deterministic cleanup on array returns and returns from catch blocks, including cases that previously skipped cleanup or freed an allocation twice.
- Fixed conditional and configuration-guarded expressions that evaluated an unselected arm or emitted calls to unavailable declarations.
- Fixed generic calls, interface and virtual dispatch, and iterator calls involving expanded arguments, concrete receivers, allocator parameters, and capability forwarding.
- Fixed prepared function and delegate calls, direct-function adaptation to delegate values, function-pointer returns, and nested callable return signatures.
- Fixed optional presence when returning struct payloads or supplying payload-valued default arguments.
- Fixed array-property indexing and updates, compound property assignments, fixed-array slice members, and const-qualified pointer access and calls.
- Fixed qualified namespace lookup, ambiguity diagnostics, and identity of same-named types in different namespaces.
- Fixed text-comparison return types, 64-bit `L` literals on Windows, signed integer literal targeting, range checks, repeated unary signs, and character and string escape validation and decoding.
- Improved diagnostics for read-only writes, invalid operator operands, uninferable `auto` declarations, generated-symbol collisions, and incompatible override defaults.
- Fixed generated API allocation-policy preservation, export-projection names, and visibility of constructor metadata and native exports.
- Fixed Linux x64 static-library compilation to produce position-independent code suitable for shared-library consumers.

## Tooling And Editor Support

- Added `campc run --show-errorlevel` to print the application's observed exit status after it exits.
- Fixed source-aware executable inference and running sources whose derived artifact filename begins with a digit.
- Compiler, imported API, and editor parsing now recognize specifier syntax consistently regardless of the selected target, with more precise specifier diagnostics.

## Documentation

- Updated the language and compiler guides for typed witnesses, lifecycle and allocation rules, visible class fields, specifier syntax, text escapes, and directory iteration.
- Clarified that optional conversions follow their payload conversion while preserving presence.

## Compatibility Notes

- Rebuild producers and consumers together when using interface tables or generic witnesses. The shared C table layout erases ordinary slot receivers and constructor results, while Camp retains their distinct source types.
- Witness function-pointer erasure is validated for x64 Clang/macOS, MSVC/Windows, and GCC/Linux Release targets. Other architectures, compiler options, function sanitizers, and indirect-call CFI configurations are not validated.
- Specifier names must use lowercase underscore-prefixed spelling. Callable carrier typespecs follow the parameter list; the old two-prefix form is invalid. Known specifier names cannot name ordinary declarations, and spec-shaped aliases declare specifier aliases. Duplicate or misplaced annotations are errors.
- Some spec-shaped parameter names require an explicit carrier specifier such as `_targettype` to disambiguate the name. Explicit `_targetcall` selects the default convention rather than inheriting a nondefault interface convention.
- Removed the unsupported `??` operator and nameless indexed-property syntax. Use a conditional expression and named indexed properties such as `value.Item[index]`, respectively.
- Deletion requires an escaped target. An interface pointer cannot be deleted directly; generic lifecycle code must retain the appropriate witness. Allocation functions used by `new` must return escaped storage.
- The compiler now rejects dangling views of local array literals, writes through read-only storage, unsupported newtype operators, invalid literal escapes or ranges, and override defaults that differ from the inherited declaration.
- Export-projection names belong to the consumer API; producer source continues to use the original declaration names.
