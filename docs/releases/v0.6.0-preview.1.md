Camp v0.6.0-preview.1 simplifies caller-prepared results, renames standard
formatting APIs to `toString`, and adds documentation metadata for richer API
surfaces.

Camp is still early preview software. Package-management commands remain
experimental and are intended mainly for Camp compiler development at this
stage.

## Compatibility Notes

Standard formatting methods are now named `toString`:

```camp
auto text = value.toString();
```

Code that called `format()` should rename those calls and custom formatting
methods to `toString()`.

Prepared-result calls now use the transformed signature by default. Ordinary
call sites no longer need the `prep` prefix:

```camp
auto text = value.toString();
```

Heap allocation for a prepared result now uses `(new)`:

```camp
auto text = (new) value.toString();
```

Prepared-result methods are no longer eligible for property accessor syntax.
Call them as methods so allocation and preparation behavior remains visible at
the call site.

## Caller-Prepared Results

- Prepared-result methods now bind through their transformed signature by
  default, making ordinary calls concise while preserving explicit
  caller-supplied-buffer calls.
- `(new) value.toString()` allocates a prepared result on the heap using the
  current allocator.
- The `prep` keyword is now contextual for parameter declarations instead of a
  general invocation prefix.
- `.length` on a prepared-result call can obtain the required buffer length
  without materializing the result buffer.

## String Formatting

- Standard-library primitive, text, and time formatting APIs now use
  `toString`.
- String interpolation holes now bind `toString` by default.
- Console and character-writer numeric output now use `toString`-based prepared
  formatting.

## Documentation Metadata

- Added documentation metadata attributes for API categorization, remarks,
  examples, parameter descriptions, return descriptions, and related API links.
- Metadata JSON now includes documentation metadata so tools can surface richer
  API information.

## Fixes

- Reduced generated C size for full-range slices.
- Reused known string lengths for full string slices, avoiding repeated
  interpolation work in generated C.
- Shortened generated C names for compiler temporaries to improve generated-code
  readability.
- Removed an obsolete language-guide note about the old `format` API name.

## Documentation And Tooling

- Updated the language guide and compiler semantics documentation for default
  prepared calls, `toString`, prepared-result allocation, property syntax
  restrictions, and prepared-result lowering.
- Updated bundled editor syntax files for the current `prep` and `toString`
  model.
