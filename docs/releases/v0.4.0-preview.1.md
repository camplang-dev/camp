Camp v0.4.0-preview.1 changes interpolated strings to produce ordinary text
values eagerly. This makes simple interpolation behave like a direct string or
character-array expression instead of a delayed formatter delegate.

Camp is still early preview software. Package-management commands remain
experimental and are intended mainly for Camp compiler development at this
stage.

## Compatibility Notes

Interpolated strings now evaluate immediately. A plain `$"..."` expression
defaults to `string`, can initialize character arrays, and can be allocated with
`new $"..."` when an escaped string is needed.

Textual `+` concatenation is rejected. Use interpolation to build a new text
value:

```camp
string message = $"{name}: {value}";
```

the legacy formatter type remains available for formatter APIs and custom formatting, but
ordinary interpolated strings no longer lower to formatter-like lambdas.

## String Interpolation

- `$"..."` now initializes `string`, `char[]`, `const char[]`, fixed
  `char[N]`, and `auto` text values directly.
- `new $"..."` allocates the interpolated text result on the heap.
- Interpolation holes are evaluated eagerly, so ordinary call and exception
  behavior applies naturally.
- Generated C for interpolation is smaller, especially for literal text and
  simple formatted values.

## Fixes

- Fixed `new $"..."` so it is not diagnosed as an escaping capturing lambda.
- Removed stale formatter-lowering behavior from interpolated strings.
- Fixed cross-file virtual class vtable linkage so public derived virtual
  classes can be constructed from another source file.

## Documentation

- Updated the language guide, semantics guide, and LLM coding guide to describe
  eager string interpolation.
