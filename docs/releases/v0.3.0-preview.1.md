Camp v0.3.0-preview.1 stabilizes string interpolation and formatter behavior,
tightens interface conversion rules, and fixes several virtual class lifecycle
issues.

Camp is still early preview software. Package-management commands remain
experimental and are intended mainly for Camp compiler development at this
stage.

## Compatibility Notes

The standard formatter type is now the legacy formatter type. This replaces the
`StringFormatter` name used in earlier `0.2.0` previews.

Code that names the formatter type directly should update declarations,
ascriptions, and custom formatter methods to use the legacy formatter type.

## Fixes

- Fixed nested interpolated strings so instance members resolve correctly inside
  nested interpolation expressions.
- Fixed interpolated string holes so receiver chains with side effects are
  evaluated once instead of repeatedly.
- Fixed interpolated strings so private members remain visible when the
  interpolation appears in a scope that can access them.
- Improved generated code for literal text inside interpolated strings by
  emitting block copies instead of one assignment per character.
- Fixed expanded array formatter receivers.
- Fixed derived virtual class deletion so generated concrete delete helpers are
  emitted correctly.
- Fixed inherited instance method calls on stack-initialized virtual class
  values.

## Conversion And Lifetime Checks

- Hardened interface pointer conversions. The compiler now rejects unsafe const
  pointer and rvalue cases instead of accepting code that could fail later in C
  emission.
- `delete this` now requires an escaped receiver. Ordinary non-escaped class
  receivers may refer to stack or otherwise non-owned storage, so deleting them
  directly is rejected.

## Documentation

- Updated formatter documentation and examples for the legacy formatter type.
- Clarified interface conversion behavior in the language and semantics guides.
